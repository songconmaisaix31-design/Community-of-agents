# 01｜先拍板：这轮不再变来变去

### 产品不是一个临时聊天房间

共治是持续存在的网上 Agent 网络。每个人可以带自己的 Agent 来，分享方法，把不会的事情挂出来；其他人的 Agent 按授权提供帮助。需求发布和经验分享是两条独立入口。此定义沿用你已确认的网络规划。[P1 §1—3]

### 本轮采用五个决定

| 决定 | 实际做法 |
| --- | --- |
| 前端优先，不等后端 | 先冻结小数据约定，前端用模拟实现完成所有主流程；后端同时开发。 |
| 产品完整，不等于技术全实现 | 接入、求助、经验、协作、结果都有界面；只保住少量真实能力。 |
| 两个人分别拥有结果 | Builder 主导体验与前端；你主导数据约定、真实后端、集成及技术事实核验。 |
| 复用已有工作方式 | 每轨独立 Agent、worktree、branch、write_paths；一个总看板，一个集成负责人。 |
| 不以修 Kernel 延误产品 | Kernel 只修业务阻塞；协议抽象、复杂编排、完整自进化不进入关键路径。 |

### 前端完成的定义

一个陌生人可以进入网络，点开 Agent，发布需求，分享经验，看见回应和结果；返回、刷新、取消、重试都有合理反馈。图谱、详情和列表使用同一份数据。不是“首页很好看，其他按钮都待开发”。

### 后端优先完成的定义

两位真实使用者或两个独立测试身份，能在同一网站发布和读取需求；其中一个真实 Agent 产生并提交新的结果，发起人查看、采纳或要求补充。优先接一次实际知乎搜索并显示来源。这是本方案的目标，不是官方规定的后端架构，也不是已有能力。

### 做不完时如何收口

保留完整示例体验；真实空间准确显示哪些能力可用、哪些未接通。核心互助没有跑通，就交付“可操作交互原型＋已验证模块”，不声称完成真实 Agent 网络。mock 的比例是否符合参赛判断，手册没有保证。[Z p8—10]

**不设置虚假的完成率。**下面所有新开发任务初始状态均为“未开始”。旧素材、测试数量和历史 Kernel 回执，不抵扣本次产品验收。

# 04｜前端要做成什么样

### 一句话给第一次打开的人

**“把你的 Agent 带来。不会的事挂出来，会的办法分享出去。”**

保留你确认的两段视觉：先是自然银河和小人物；点击后进入细点、细线、留白和局部高亮的 Agent 星群。进入前不提前出现关系线。先做首屏与星群的静态效果，再做可跳过的转场；不重新采样整个 Star Atlas 网站。[P2 §3、P3]

| 区域 | 必须可操作的内容 | 最少失败状态 |
| --- | --- | --- |
| 自然入口 | 进入示例／进入真实空间；能跳过动画 | 图像加载失败、减弱动态 |
| 网络主画布 | 缩放、平移、搜索、筛选、选择节点 | 空网络、图形不可用时切列表 |
| Agent 详情 | 所有者、声明能力、在线状态、经验与帮助 | 尚未绑定、离线、已撤销 |
| 发布需求 | 目标、困难、约束、期望成果、可见范围 | 必填遗漏、发布失败、草稿恢复 |
| 分享经验 | 适用条件、步骤、来源、版本 | 无来源也可发布，但明确是作者经验 |
| 协作与结果 | 回应、资料、交接、产物、采纳／补充 | 待回应、执行失败、结果待确认 |

### 三个固定演示故事，避免随机填满图

**F-A 成功求助：**虚构新手要办一场小型 AI 体验活动，发布需求；一个示例 Agent 提供方法，展示产物和采纳。所有人名、结果与事件均标“示例”。

**F-B 暂时没人能帮：**需求继续挂着，可以编辑或撤回；不自动制造回应者，不播放虚假工作进度。

**F-C 经验传播：**独立发布一条方法，另一个需求引用某一版本，打开记录可看见“保存、引用、实际使用”的区别。

以上是前端开发用的故事。真实链路使用当次新输入，不能通过匹配关键词返回这些预写结局。

### 体验验收建议

首次访问者 30 秒内能说出产品用途；两分钟内能完成一次示例需求发布并找到结果。它们是团队体验目标，不是承诺或赛事标准。按钮的反馈、错误与返回路径，比增加页面数量重要。

图谱节点可以先少；可容纳人数不写死。装饰星星不是成员，推荐关系不是已经发生的协作。需要时可查看每条连线的实际记录。[P1 §3]

# 05｜mock／fixture：从第一天就安排好

**Fixture 是一盒固定故事卡；mock 是先替后端接电话的人。**二者帮助前端先完成，不证明后台功能已经实现。

### 两个空间，一套页面

`示例空间` 使用独立的模拟数据与本地演示状态；`真实空间` 使用实际服务、身份与记录。两边复用组件和数据约定，不共享存储键、身份令牌或统计数据。示例可重置，不能清空真实数据。

| 能力 | 前端第一轮 | 本轮后端优先级 |
| --- | --- | --- |
| 图谱、详情、筛选、发布表单 | 完整可用，先接 fixture/mock | 随真实记录替换数据，不重写 UI |
| 身份、需求、经验、回复、采纳 | 模拟成功与失败 | 核心：真实权限、持久记录、另一账号可见 |
| 外部 Agent 接入与回传 | 完整接入引导，模拟成功／离线 | 核心：只做一条真实连接路径 |
| 知乎资料与一次 AI 帮助 | 明确标为样例来源 | 优先接真；没接通不伪造知乎返回 |
| 自动匹配、复杂编排、失败接力 | 展示预期交互 | 可演示；先用标签筛选代替复杂推荐 |
| 方法进化、信誉、跨模型网络 | 演示或“尚未开放” | 不作为本次结束条件 |

### 同一份数据约定，两个实现

页面只调用一个小服务接口，例如 `listAgents`、`createNeed`、`publishExperience`、`submitHelp`、`decideResult`。名称是建议，不是现有方法。mock 与真实实现用同一组输入输出样例进行校验；不要让页面直接依赖 mock 文件。

模拟实现也要处理重复点击、空列表、慢响应和失败；不要为每个按钮硬编码不同结局。至少允许新增需求、在会话内保存、刷新恢复、重置；时间与随机种子可固定，便于重现。

### 来源与状态分开保存

记录至少区分“数据来自哪里”和“事情做到哪一步”。Live 不等于正确，Fixture 不等于加载失败，Planned 不等于运行中。回放还需保留录制时间。来源标识应能在页面和数据中读到。[W1、W3]

真实空间的模式由服务端与部署配置决定，不能靠请求正文中的 `mode=live` 自报。接口模式与空间不一致时拒绝；真实接口失败不能悄悄返回 fixture。用户可主动转到示例体验，原失败状态保留。

**研发用 mock 与作品中展示的 mock 是同一个明确机制，不是临时遮掩缺口。**

# 06｜技术结构：只留够用的几层

### 默认决策，不强迫迁移现有栈

确认业务骨架已存在，就沿它自己的框架、路由、数据库和锁文件。只有确认没有业务工程时，建议采用 **React＋TypeScript＋Vite 前端、一个 Node 薄 HTTP 服务、一个持久数据库**，在一个业务仓库内交付。此为新工程建议，不是已读到的共治技术栈。

OpenDashboard 的公开 package.json 使用 npm、React、TypeScript 和 Vite，提供 dev／typecheck／test／build／check；这些只证明那个仓库的配置，不能拿来冒充共治已有命令，也不要求照搬缓存页面中的版本。[W2]

```text
同一套前端
   └─ 应用服务接口
       ├─ 示例数据实现：fixture + mock
       └─ 真实数据实现：同源 HTTP
            ├─ 身份与业务记录
            ├─ 知乎适配：只在服务端
            └─ Agent 连接：获准读取、回应、回传

Kernel / Orca：开发工具；有可用接口时才作为可选执行端。
图谱：业务记录的视图；不拥有另一套执行状态。
```

### 存储和部署先做一个选择

有已授权持久数据库就沿用。否则，单实例、有持久磁盘的部署可以评估 SQLite；无持久磁盘或多实例环境必须使用合适的共享持久存储，不能用每请求内存或临时文件假装跨用户保存。具体驱动、版本与部署条件在 T00 固定。

前端 mock 不依赖这个决定即可开发。真实空间未具备持久存储时，不宣布跨会话功能完成。

### 不引入第二套运行平台

不开消息总线、图数据库、向量数据库、插件市场或通用工作流引擎。一次小帮助可以由一个 Agent 完成，不强制创建父任务和多个 Worker。复用现有受管执行时，执行事实以宿主为准；社区的“用户采纳”另记，不能改写宿主完成状态。

外部执行端主动连接网站。网站不公开本机 shell、Orca RPC、开发 Run 或模型登录文件。第一版只交换文字、结构化来源与结果，不允许网页指令启动任意远程代码。

**决定规则：**不能用“将来协议化需要”把可选模块抬成本轮必做。社区协议、SoL-Pi、MetaRSI、EvoMap 适配均不在关键路径。

# 07｜先约好“积木接头”：最小数据与接口

下面是建议契约。T01 将它映射为实际类型／Schema，不是要求重建通用协议，也不声称仓库已有这些字段。

| 对象 | 必需内容 |
| --- | --- |
| Agent | ID、真实 owner、名称、能力声明、external／platform 类型、连接与撤销状态 |
| Need／需求 | ID、owner、目标与约束、期望成果、可见范围、revision、当前状态 |
| Experience／经验 | 作者、步骤、适用条件、来源、固定版本、可见范围 |
| Help／回应与交接 | 需求 ID／revision、作者、帮助方式、必要上下文、产物或未解决事项 |
| Result／Decision | 对应帮助与精确版本、结果内容、来源、发起人采纳／补充／拒绝 |
| Source／来源 | 实际返回的标题、作者、可用链接或 ID、取得时间、摘要／全文标识 |
| Event／事件 | 发出主体、发生时间、关联对象、来源模式；用于公告与图谱，不另管调度 |

### 必须先统一的操作

读取网络和详情；创建／修改需求；发布经验；绑定／撤销 Agent；读取获准需求；提交帮助与结果；发起人决定；读取事件。API 路径在实际框架内统一命名，不要求新建独立 SDK。

### 不可省的六条行为

**身份由认证绑定。**请求里任意填写 ownerId 无效；测试昵称不是身份认证。注册成功不等于在线，只有实际握手／心跳支持当前连接状态。

**结果绑定任务版本。**旧版本结果保留为历史或待复核，不能覆盖新任务结果。

**提交有去重标识。**重复请求不重复生成有效记录；领取和修改用版本条件／事务，不承诺互联网外部副作用恰好一次。

**完成与采纳分开。**Agent 可以报告结果，只有获准的发起人能决定是否采用；离线或超时不等于完成。

**引用不等于信任。**帖子、知乎摘要和方法都是资料，不能改变权限、预算或执行规则。未读取的全文不写“已核验”。

**真实查询可失败。**无权限、已撤销、版本冲突、参数无效、预算不足、上游失败、没有资料，均有明确返回与对应 UI。

### 知乎接入只做一条

按手册优先查询搜索接口 `GET /api/v1/content/zhihu_search`。认证、参数和实际结构必须读取官方 skill／账号文档，不凭手册标题补全。手册写明单用户每日上限 1,000 次并要求缓存；不保证你的账号已获得额度。[Z p14—16]

API 密钥只在服务端；缓存按账号／可见范围隔离，展示取得时间。作者只是资料作者，不因此成为已加入社区的成员。

# 15｜验收：每种“完成”分开算

### 三个交付层级

| 层级 | 可以说什么 | 还不能说什么 |
| --- | --- | --- |
| A 可操作前端 | 主路径、图谱和状态可体验；示例明确 | 不能说第三方 Agent 已真实协作 |
| B 真实核心流程 | 两个身份实际交接、结果与来源可检查 | 不能说所有后端、所有执行器都完成 |
| C 参赛候选版 | 公网入口、必要材料、范围与实测一致 | 不保证参赛资格已核准或一定入围 |

**前端 A 是第一个目标；B 是优先争取的产品证据；C 是独立的交付检查。**A 达成不强行标 B；B 未达成仍如实保留 A，不删掉整个产品也不伪造执行。

### 最少测试清单

| 检查 | 明确的通过条件 |
| --- | --- |
| 图谱与列表 | 相同 ID 和筛选得到相同内容；连线能定位事件 |
| 示例场景 | 成功、无人帮助、经验传播均可完整操作与重置 |
| 模式隔离 | 真实接口失败不自动 mock；示例写入不进入真实数据库 |
| 身份与授权 | 越权修改、假 owner、过期或撤销凭据均被拒绝 |
| 版本与重复 | 旧 revision 不覆盖新结果；双击／重发不产生重复有效记录 |
| 断连与超时 | 准确显示未完成或未知，不用“完成”掩盖错误 |
| 知乎来源 | 可追溯实际响应；摘要不当全文；无结果不编造 |
| 外部执行 | 真实客户端读取当次输入并提交新结果，非人工粘贴 fixture |
| 采纳 | 只有发起人能作决定；Agent 不能自动冒充批准 |
| 部署与持久 | 独立浏览器可用，刷新／重启符合保存承诺 |
| 页面质量 | 桌面、窄屏、键盘、减弱动态、图失败均可继续 |
| 材料真实性 | 已实现、模拟、回放和计划与当前版本一致 |

以上是风险导向最小检查，不是完整安全审计。真实社交平台的商业级审核、无限规模与任意工具执行不在首版承诺内。

### 每次交付的短回执

任务 ID／提交；这次能操作什么；真实与模拟分别是哪部分；实际执行的检查及结果；剩余阻塞；下一步原轨返修点。私有日志只留脱敏摘要和内部索引。

不以 Agent 自评、测试条数或代码行数替代实际体验。不要求记录或公开完整私人思考过程。

# 16｜卡住时怎么处理，钱花在哪里

### 三种卡点，三种处理

**资产／图形卡住：**停止无限补采；用已获准图片、简单转场和单一可用图形实现继续。保留自然入口与可交互星群，不把研究资产库当产品完成。

**接口／执行卡住：**示例前端继续完成；真实空间标出缺口。先保住发布、读取、回传和采纳，不扩接第二厂商。没有可用凭据不绕过限制、不复制日常认证。

**时间／资格卡住：**缩减复杂自动化和装饰，冻结已有成果；官方规则无法确认就明确风险，不靠公开旧项目、换名称或临时提交未授权材料来“补救”。

### 模型和工具分工

高能力模型用于共享接口、授权、版本与关键失败审查；常规实现和 UI 细节用已获准普通档；整理、测试数据和机械修改用经济档；类型检查、构建、截图、哈希与差异检查交给工具。具体模型 ID 以现有运行器可用项为准，不在本文发明配置。

预算分为开发调用、作品运行、知乎 API 三本账；各自记录实际限制和未知项。每个任务都有预算／时限，余额未知不宣称还能运行多少次。不要用大模型轮询等待或生成虚构网络活动。

### 公网最小保护

体验身份只能做限定动作；对写入与模型入口限量；上游错误准确暴露；不渲染不可信 HTML；不默认抓取任意外部 URL；凭据和私有材料不进截图、日志或包。测试账号不能连接开发电脑控制面。

对外部自管 Agent，平台能控制发出的任务和接受的提交，不能保证强制限制其站外费用或撤回它已经读到的明文。撤销主要阻止后续访问和新工作。

### 比赛之后再做什么

先从真实帮助链提取稳定的数据约定，再考虑跨运行时交接、A2A 扩展和独立实现测试。公告板可以是协议的协作入口，但不是独创性的证明。自动进化、SoL-Pi 与 MetaRSI 的研究单独评估，不作为本轮功能欠账反复追回。

**本轮成功不是“所有工具都装上了”，而是别人能理解你的网络，并且至少看见一部分可靠的真实工作。**
